# Changelog

## [Unreleased]

### 2026-07-17
- **fix(pack):** `iso` no longer picks an arbitrary `coreos-*.iso` from the store. A store is content-addressed and shared, so it can hold several releases and arches at once; selection is now anchored in provenance — match `provenance/release-*.json`, follow the `machine-os-images` component to that image's recorded layer dirs, and take the ISO from there. New `IsoSelector` (`--release <version-or-digest-prefix>`, `--arch <x86_64|amd64>`, either spelling accepted); an ambiguous or unmatched selection is an error listing the candidates/available releases rather than a coin flip. Stores with no release provenance fall back to a scan that still refuses to guess between multiple hits. `iso` now also prints the release it resolved. Fixed a stale `--version` example in the README.
- **fix(compose):** Staging no longer silently produces a partial or unverified artifact set. Each `Artifact` now carries a `required` flag; the boot trio (kernel + initramfs + rootfs) is required, so a fetch/verify failure on any of them fails the whole command instead of being logged and skipped (a post-loop invariant re-checks every required role is present). Offline mode with no cached `sha256sum.txt` now **fails closed** rather than skipping verification — an online run leaves the checksum file in the cache, and a new `--insecure-skip-verify` flag is the explicit, loudly-logged opt-out for building from unverified media. Tests cover the offline checksum decision and the required-set guard.
- **fix (deps):** `rspacefs-verity` is now a **git-pinned dependency** (`rev = 71b44a7`) instead of a `../rspacefs` path dep, so downstream consumers (stormcos) can take `rspaced-oci`/`rspaced-pack` as git deps without a sibling checkout. Commented `[patch]` block in `Cargo.toml` documents the local-sibling dev loop. CI (`build.yml`, `release.yml`) no longer clones the rspacefs sibling. Closes [#1](https://github.com/glennswest/rspaced/issues/1).

- **chore:** Created GitHub repo `glennswest/rspaced` (public) and pushed initial commit.

Implements RHCOS mirror version discovery, atomic download, sha256 verification, and online/offline staging into a local cache. `files` output is functional; `registry`/`iso`/`pxe`/`raw`/`qcow2` are scaffolded stubs. Makefile wraps cargo.
- **docs:** Added `compose_rspaced/ARTIFACTS.md` (artifact → role → image → rspacefs registry map; online/offline workflow) and `rspaced_agent/DESIGN.md` (live-boot → pull-from-rspacefs → self-install → pivot-without-reboot; registry split; PVC config/push-back).
- **feat:** Made the central registry optional. `offline` mode now builds from the local cache / local rspacefs without requiring `--registry`; a registry is only needed for the `registry` push subcommand. ISO/PXE builds can run with no central registry at all.
- **feat:** Converted rspaced to a cargo workspace and added `crates/rspaced-oci` — an OCI Distribution v2 pull client + image types ported from fastregistry (`pkg/digest`, `pkg/oci`, `internal/sync/{registry,quay}.go`). Includes the `WWW-Authenticate: Bearer` challenge → token-exchange flow for anonymous quay.io pulls (validated live against `quay.io/openshift-release-dev/ocp-release:4.18.30-x86_64`).
- **docs:** Added `enhancements/multi-registry-boot.md` (rspacefs-side spec): registry routing by content type + ephemeral-then-persistent PVC lifecycle, targeting `rspaced_agent` + `compose_rspaced`.
- **feat:** Added `crates/rspaced-pack` — pulls OCI images via `rspaced-oci` and extracts their layers into rspacefs layer directories (`extract_layer`, `pack_image`; OCI `.wh.` whiteouts preserved, digest-verified, idempotent, returned in `LayerFS` lower order), plus OpenShift release-payload discovery from `release-manifests/image-references`. Validated live: packed `quay.io ocp-release:4.18.30-x86_64` and discovered 188 component images in the Red Hat registry.
- **feat:** Provenance-tracked store + full release payload pull (`compose_rspaced release`): content-addressed OCI blob store preserving original manifests/index/config/compressed-layers by digest; per-layer hash chain (compressed digest → `diff_id` vs image config → `rspacefs-verity` Merkle root); `ImageProvenance`/`ReleaseProvenance` JSON. `build_from_dir` (symlink-aware) verity after rspacefs#18 fix; `force_remove_dir_all` for read-only image dirs on resume.
- **feat(deploy):** Provisioned `rspaced.g8.lo` build/run/control host (Proxmox VMID 120 @ 192.168.8.160, Fedora 43) via cloud-init: 64G root + persistent 800G `/data` (survives OS wipe) + MicroDNS record. Assets in `deploy/`.
- **ci:** Added forcicd build workflow (`.github/workflows/build.yml`) — `fmt`/`clippy`/`test`/`build` on the Forgejo/act_runner mirror, checking out `../rspacefs` as a sibling for the path dep. First run green on forcicd.
- **feat(release):** RPM packaging (`cargo-generate-rpm`) + `release.yml` publishing the RPM to the **local cicd** (Forgejo on forcicd.g8.lo, not github) via the runner token. `deploy/install-on-rspaced.sh` does cleanup-before (`dnf remove`) then install-after (`dnf install`), resolving the newest RPM from the local cicd.

- **test:** End-to-end validated on rspaced.g8.lo (VMID 120): cicd-built RPM installed; release image (anonymous) + component payload (authenticated) packed with per-layer `diff_id` + `rspacefs-verity` roots + provenance JSON, into persistent `/data/store`. 188 components discovered; bounded pull (3) packed 0-failed with shared-layer dedup.
- **feat:** `compose_rspaced verify --store` — re-hash every preserved blob against its digest and rebuild each extracted layer's verity root, comparing to recorded provenance (the at-rest integrity re-check; exits non-zero on mismatch).

Manual multi-pass extractor also defers read-only directory modes and refuses path-traversal entries.
- **perf:** Per-layer verity caching — an already-packed layer (marker + `.verity.json`) reuses its Merkle manifest instead of rebuilding, so shared base layers aren't re-hashed across the 188 components.
- **test:** Full OCP 4.18.30 payload pulled + packed end-to-end on rspaced.g8.lo — all 188 components (incl. rhel-coreos) + the release image, 58G on `/data`. `verify` over the whole store: **189 images, 1180 blobs + 802 verity roots, 0 failures**.
